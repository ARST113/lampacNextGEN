# MPV2 NextGen: правки по итогам живых тестов (11.10.2026)

Устройство: Pixel 10, Android 17, **системный WebView 154** (`wv … Chrome/154 … lampa_client`),
`crossOriginIsolated = false`, `SharedArrayBuffer` отсутствует. Десктоп: Chrome 153.

Ниже — что именно ломалось в бою и что поправлено. Телеметрия собиралась зондом
`Modules/LampaWeb/plugins/mpv2-probe.js` (маячки уходят в лог сервера: окружение, конфиги
`VideoDecoder`, ошибки, события `<video>`, внутренний лог плеера `window.__mpvwasm_log`).

## 1. MPV2 вообще не стартовал: `SharedArrayBuffer is not defined`

`mpvwasm-demuxer.js` — pthread-сборка FFmpeg WASM, ей нужен `SharedArrayBuffer`, который браузер
выдаёт только страницам с cross-origin isolation. В системном WebView страница изолированной не
становится, поэтому демуксер не грузился и плеер падал до первого кадра.

**Фикс:** `mpvwasm-demuxer-session-worker.js` и `mpvwasm-demuxer-wrapper.js` выбирают сборку по
возможностям движка:

```js
var SINGLE_THREAD = !(typeof SharedArrayBuffer !== 'undefined' && self.crossOriginIsolated);
// isolated (Chrome/десктоп) -> mpvwasm-demuxer.js     (pthread, как было)
// Android WebView          -> mpvwasm-demuxer-st.js  (single-thread)
```

Плюс цепочка кандидатов (если выбранная сборка не поднялась — пробуется вторая) и предзагрузка
именно той сборки, которая будет использована. В `assets` добавлены `mpvwasm-demuxer-st.{js,wasm}`
(FFmpeg 7.1, `-sUSE_PTHREADS=0`, `-sWASM_BIGINT=1`) и legacy-пара для WebView < 85.

## 2. AV1: неверная кодек-строка и неподходящий `description`

Было жёстко: `candidates('av01.0.12M.08', description)`. Для HDR10-релизов поток 10-битный
(`yuv420p10le`, `smpte2084`), а строка `.08` описывает 8 бит → мгновенный `Decoding error`.
Плюс FFmpeg/Matroska отдаёт в `extradata` не `av1C`, а **sequence header OBU**, который в
WebCodecs передавать как `description` нельзя.

**Фикс:** строка собирается по треку (`profile`/`level`, битность — по HDR-признакам
`colorTransfer`/`colorPrimaries`), `description` для AV1 не передаётся (sequence header приходит
в самих пакетах).

## 3. AV1 всё равно нестабилен в WebCodecs

Демуксер отдаёт AV1 **по одному OBU на пакет**. Проверено инструментально:
- подача по одному OBU → декодер (dav1d) падает с `error -22` на ~38-м кадре;
- разбиение по кадрам → падение ещё раньше;
- укрупнение в пачки по 32 OBU → падение на втором чанке;
- один большой чанк на 2 с (склейка OBU) → 54 кадра без ошибок, но корректные таймстемпы на
  отдельные кадры при этом теряются, а A/V-часы MPV2 строятся именно на них.

При этом тот же файл **нативный `<video>` играет без единой ошибки** (проверено 40 с подряд,
аппаратный AV1-декодер устройства).

**Решение (временно):** AV1 уходит на нативный плеер осознанно —
`throw new Error('av1-native-preferred: …')` в `init()` гибрида, игрок ловит это и вызывает
`activateNativeFallback('av1-native')`. Правки кодек-строки и сборки OBU при этом остаются в коде
(включаются через `options.allowAv1`), чтобы можно было вернуться к задаче.

## 4. Аппаратный декодер не даёт ни одного кадра — нет повтора

Раньше единственным исходом был откат на нативный плеер. Теперь: если за 6 с не отрисовано ни
одного кадра и выбранный конфиг был аппаратным — один повтор с `forceSoftware`
(`prefer-software` первым в списке кандидатов), и только потом откат. Флаг для диагностики:
`Lampa.Storage.set('mpvwasm_force_software','true')`.

## 5. Откат на нативный плеер оставлял «Decoding error.» на экране

`activateNativeFallback` теперь гасит текст ошибки (`lastError`, `PlayerInfo.set('error','')`),
индикатор загрузки и статус — раньше сообщение висело поверх уже играющего видео.

## 6. Панель исчезала мгновенно после тапа

Контроллер `mpvwasm_player` имел `toggle: function () { hidePanel(); }` — безусловное скрытие.
Lampa дёргает `toggle` текущего контроллера на каждый тап, поэтому панель показывалась и тут же
пряталась. Теперь это честный переключатель (`state.panelVisible ? hidePanel() : showPanel()`).

## Что осталось нерешённым

- **AV1 внутри WebCodecs** — нужен корректный сбор OBU в temporal units с сохранением таймстемпов
  (задача открыта, см. п. 3).
- **AAC/звук**: в части прогонов звук не слышен (в бою — на потоке с `eac3,ac3,eac3`).
  Нужна отдельная проверка аудиотракта гибрида на устройстве.
- **Производительность 4K HEVC**: ~11 fps отрисованных кадров, сотни дропов, звуковые underruns;
  аппаратный декодер работает, узкое место — рендер и звуковой конвейер.
- **UI-паритет со штатным плеером** не закончен (панель, шкала прогресса, поведение).

## Как проверялось

- `node --check` всех изменённых JS, `node --test tests/mpv2-nextgen-audio.test.js` — 9/9;
- живые прогоны на десктопе (AC3 5.1 MKV, HEVC 4K AV1-файлы через `mpvwasm/proxy`);
- телеметрия с телефона (маячки `mpv2-probe`) и логи nginx: подтверждено, что на устройстве
  выбирается `mpvwasm-demuxer-st.js`, `SharedArrayBuffer` отсутствует, а AV1-поток валит декодер.
