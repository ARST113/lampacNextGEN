# MPV2 NextGen — экспериментальный аудио/4K/UI-проход

Дата: 2026-10-10. Ветка: `feat/mpv2-nextgen-audio-perf-ui-20261010`. **Не включать по умолчанию и не переносить в main без проверки на Android TV.**

## Что изменено

- `mpvwasm-audio-worklet.js`: интерполяционный PCM ресемплинг `source sample rate → AudioContext.sampleRate` с PTS-часами, недозаполнения не продвигают часы. Стерео-downmix только при двухканальном выходе; выход 6/8 каналов может передавать их раздельно.
- `mpvwasm-hybrid-webcodecs.js`: число выходных каналов выбирается по `audioContext.destination.maxChannelCount` и каналам исходника, есть ручной безопасный режим `stereo`. Ограничены 4K decoded-frame queue `48→8`, packet queue `144→36`, decode queue limit `64→12`. Метрики обновляются в реальном времени: fps, decoded/dropped, A/V drift, аудиоканалы и underruns.
- `mpvwasm-lampa-player.js`: исходные шаблоны и CSS Lampa используются как основа, добавлены настройки аудиовыхода/рендерера, диагностика воспроизведения, поддерживаемый HTML5 PiP, исправлен fit mode `fill`.
- `mpvwasm-lampa-loader.js`: обновлён cache-busting версии загрузчика.
- `tests/mpv2-nextgen-audio.test.js`: синтетические проверки 44,1→48 кГц, сохранения PTS, pause/reset, раздельного 5.1 и понижения 7.1→5.1.
- CI workflow проверяет синтаксис и тесты Node.

## Ограничения текущего шага

1. **Аппаратное декодирование видео** через WebCodecs определяется платформой; `VideoDecoder` и `isConfigSupported` сами по себе не доказывают использование GPU. Canvas 2D/WebGL может быть дополнительным узким местом 4K, HDR/Dolby Vision необходимо сверять визуально с нативным HTML5 плеером.
2. **5.1/7.1** — PCM-маршрутизация в Web Audio. Она не гарантирует системный HDMI passthrough AC3/DTS/TrueHD и не доказывает, что OS/ресивер не сведёт каналы в 2.0 после браузера. Показатель `maxChannelCount >= 6` необходим для режима, но недостаточен как сквозное подтверждение.
3. **CPU/4K и A/V drift** пока имеют профилирование/предварительные кодовые исправления, а не измеренный результат на реальном Android TV. Большие очереди уменьшены экспериментально; при реальном starvation пороги подбираются по trace.
4. Новая панель основывается на актуальных шаблонах Lampa (аудио, субтитры, плейлист, перемотка, громкость, полноэкранный режим). Полный feature parity требует дополнительных отдельных интеграций: playback-speed с pitch-preserving аудио, skip intro/credits, пользовательские субтитры и PiP для Canvas (невозможно дать как нативный PiP без отдельного video-суррогата).

## Контрольный план на целевых устройствах

| Тест | Что записать | Критерий |
|---|---|---|
| CPU / 4K | Chrome/WebView trace, ADB `top -H`, декодер/GPU, потребление памяти | Сравнить с предыдущим MPV2 и HTML5 на одинаковой сцене, отсутствие устойчивого роста памяти |
| 4K HEVC/HDR | fps, droppedFrames, decodeQueue, buffering, видеоцвета, seek | Проверить p24/p60 на 5, 15, 30 мин и после перемоток |
| A/V sync | driftMs, audible lip sync, underruns, частоты 44.1/48 kHz | Нет нарастающего отклонения после 30–60 мин; целевой drift +/-80 мс без буферизации |
| 5.1 | тестовый сигнал по очереди FL/FR/FC/LFE/SL/SR | Позиции реально различаются на AV-ресивере/6-канальной звуковой карте |
| Выбор дорожки | 3–8 дорожек AC3/EAC3/DTS/AAC, переключение в начале и середине | Видео не перезапускается, нет затяжной тишины/потери таймлайна |
| Lampa UI | ДПАД, touch, Esc/Back, плейлист, субтитры, настройки | Контроллеры Lampa не застревают, элементы в формате native templates |

Для качества диагностики сначала проверить по ссылке MPV2 Settings → «Диагностика A/V и 4K»; в консоли `window.__mpvwasm_hybrid_debug`, `window.__mpvwasm_hybrid_timing`.

## Принцип аудиочасов

Аудио управляет воспроизведением видео: каждая порция PCM содержит собственный PTS и sourceRate. Worklet преобразует число source-frames, потреблённых на output-frame, как `sourceRate / audioContext.sampleRate`. Clock = `PTS + consumedSourceFrames / sourceRate`. Пауза и underrun не двигают PTS. Это исправляет систематическую ошибку скорости 44.1→48 kHz; для реального A/V sync всё равно нужна проверка смещения аппаратного аудиовыхода и видеорендерера на живом устройстве.
