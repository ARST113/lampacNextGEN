# PidTor NextGen: мгновенный буфер и быстрое переключение качества (2026-10-17)

Сборка `20261017-80-warm-stream`, файл `/home/lampac/module/PidTor/plugin.js`
(md5 `66e9331a10ee659f608440c60c3f63a2`). Только `plugin.js`, перезапуск lampac не нужен.

## Что было медленно

1. Окно наполнения (`fillBuffer`) открывалось только после того, как `attachExternalQuality`
   отдаст списки качеств — до 1.5 с ожидания на ровном месте. В это время TorrServer ещё
   ничего не качал.
2. Тёплый запрос к потоку (он же — единственный триггер предзагрузки TorrServer `preload=32`)
   уходил только из этого окна, то есть после резолва потока и сборки качеств. Замер на
   сервере: после такого запроса первые байты появляются ~3.7 с, 8 МБ ~5.5 с — всё это время
   в окне висело «0.0».
3. При переключении качества внешний плеер идёт на URL другого качества напрямую, минуя
   плагин, а TorrServer до этого адреса ничего не качал: каждый переключатель стартовал с
   нуля (метаданные, пиры, первые байты).

## Что изменено

- **Окно и предзагрузка стартуют сразу** по готовности потока: `startBufferWindow()` открывает
  окно и запускает тёплый запрос, `attachExternalQuality` догружает списки качеств параллельно;
  передача в плеер ждёт и буфер, и списки (`preload.then(handOff)`).
- **Тёплый запрос уходит на нажатие**: `warmChosenEpisode()` в `launch()` сразу запрашивает
  поток выбранного качества для выбранной серии (реплика с нужной аудиодорожкой; список серий
  уже в очереди префетча). Пока PidTor резолвит поток (торрент, проба), TorrServer уже качает.
- **Все качества греются после передачи потока**: `warmQualityVariants()` по одному раз в 1.5 с
  запрашивает остальные качества текущей серии из карты качества. К моменту, когда зритель
  откроет «Качество видео» в плеере, они уже наполняются. Цепочка останавливается при новом
  запуске, адреса помнятся 4 минуты (`warmStreams`), повторных запросов нет.
- `fillBuffer` больше не делает собственный тёплый запрос — он идёт через `warmStream()`
  (дедупликация). Окна отменённых запусков не мешают новому: `stale()` по
  `pidtor_playlist_session`.
- Опрос состояния буфера 500 мс вместо 700 мс — проценты/скорость обновляются живее.
