## Признак

На ТВ (MiTV, Lampa Android) выбираешь 5-ю серию — играет она, но плеер считает её первой:
нумерация начинается с неё, после 8-й идёт 1-я. Это следствие прошлой правки: плейлист
разворачивался так, чтобы выбранная серия была первой записью.

## Как это устроено у штатной Лампы

`app.min.js`, ветка Android в `start()`:

```js
data.url = Torserver.toPlayUrl(data.url);
data.playlist.forEach(a => { a.url = Torserver.toPlayUrl(a.url); ... });
Android.openPlayer(data.url, data);
```

Приложение Lampa (`MainActivity.runPlayer`) строит плейлист из `data.playlist` и ищет стартовую
запись по url:

```kotlin
val currentIndex = playlist.indexOfFirst { it.url == videoUrl }.coerceAtLeast(0)
```

и далее `createBaseIntent` играет `playlist[currentIndex].url`. То есть номер серии в плеере —
это **позиция записи, чей url совпал с переданным**; промах молча даёт индекс 0 (первая серия).
Порядок записей = порядок торрент-файлов, ничего не переставляется.

## Почему совпадения не было

Перед передачей Lampa `Player.play` подменяет `data.url` на «качество по умолчанию»
(`video_quality_default`, по умолчанию 1080) из верхней карты `quality`:

```js
if (data.quality) { ... data.url = getUrlQuality(data.quality, false); }
```

А в плейлисте у этой же серии оставался реально запущенный/прогретый url (например 2160).
`indexOfFirst` не находил → старт с записи 0. Прошлая правка разворачивала список, чтобы
промах попадал в нужную серию — ценой нумерации.

## Что изменено (`externalHandOffItem`)

* Список всегда в естественном порядке `1..N` (без разворота).
* Запись запускаемой серии получает ровно `launch.url` — тот url, который Лампа передаст
  (`copy.url = launch.url`), поэтому `indexOfFirst` находит нужный индекс. Если url не найден в
  списке (перерезолв), запись ищется по `season/episode` и url проставляется.
* При передаче списка верхняя карта `quality` удаляется — иначе Lampa подменяет url и совпадение
  снова ломается. Панель качества при этом не теряется: клиент строит элементы плеера из
  `playlist`, и **у каждой серии в списке своя карта качества** (`pidtor_quality_episodes`).
* Для одиночного элемента (фильм, либо `playlist_next` выключен) верхняя карта остаётся — там
  нет списка, с которым надо совпадать, и качество читается из самого элемента.

## Проверка

`pidtor-work/test-handoff.js` — офлайн-стенд: вырезает реальные `externalHandOffItem` /
`externalTransportCopy` / `externalCardCopy` из файла и прогоняет через копию двух стадий —
`Player.play` (подмена качества) и `runPlayer` (поиск индекса). Фикстура: 8 серий, 4 качества,
нажата 5-я.

```
node test-handoff.js        # 45/45
```

Что показывает старый и новый код (выбрано 2160p, по умолчанию 1080):

* до разворота: `index=0 ep=1` — играет первая серия (исходный баг);
* развёрнутый (был задеплоен): `index=0 ep=5 order=[5,6,7,8,1,2,3,4]` — серия верная, но она
  «первая» и после 8-й идёт 1-я (жалоба);
* новый: `index=4 ep=5 order=[1,2,3,4,5,6,7,8]` для любого выбранного качества; карта качества
  есть у каждой серии; для фильма карта сохраняется.
